# «Хроники преображения Мира»

Восстановленная версия авторского сайта Ирины Ниловой и самостоятельная редакционная система. Сохранённый архив старого WordPress-сайта работает вместе с новой CMS: редакторы могут создавать, редактировать и публиковать материалы без доступа к исходному хостингу.

## Что уже включено

- 1197 восстановленных страниц и совместимый адрес `/library/book/`;
- 1100 опубликованных материалов WordPress в редактируемой базе, включая все 469 записей раздела «Новости»;
- категории старого сайта: новости, мероприятия, творчество и блоги;
- черновики, публикация по дате, архивирование и история редакций;
- форматирование текста, изображения, PDF, дополнительные ссылки и SEO-поля;
- роли «Администратор» и «Редактор»;
- локальные защищённые загрузки и SQLite без внешней базы данных.

## Локальный запуск

Требуется Node.js 22.13 или новее.

```bash
npm install
cp .env.example .env.local
```

В `.env.local` задайте уникальные `CMS_ADMIN_EMAIL` и `CMS_ADMIN_PASSWORD`, затем выполните:

```bash
npm run cms:init
npm run dev
```

Сайт откроется по адресу `http://localhost:3001`, редакция — `http://localhost:3001/admin`.

Первый запуск создаёт администратора и однократно импортирует новости. Изменение `CMS_ADMIN_PASSWORD` после этого не меняет пароль существующего пользователя — используйте раздел «Профиль» в CMS.

## Поля материала

- заголовок и постоянный адрес страницы;
- краткое описание и форматированный основной текст;
- категория из восстановленной структуры сайта;
- статус: черновик, опубликован или архив;
- дата публикации, в том числе будущая;
- обложка с альтернативным описанием;
- произвольные внешние ссылки в формате `Название | https://адрес`;
- отдельные SEO-заголовок и описание.

Администратор может добавлять пользователей, менять их роли, отключать доступ и выдавать новый пароль. Каждый пользователь может самостоятельно сменить свой пароль в профиле.

## Проверка перед выпуском

```bash
npm run lint
npm test
```

`npm test` выполняет производственную сборку, проверяет очистку HTML, пароли, сигнатуры файлов, миграцию SQLite, индексы и импорт всех 1100 материалов.

## Развёртывание через Docker

Создайте рабочий файл окружения:

```bash
cp .env.production.example .env.production
```

Укажите новый домен в `SITE_URL`, уникальную почту администратора и длинный случайный пароль. Затем:

```bash
docker compose up -d --build
```

Приложение будет доступно на порту 3000. Перед ним следует настроить HTTPS-прокси (например, Caddy или Nginx). База и загрузки находятся в постоянном Docker-томе `cms-data` и сохраняются при пересборке контейнера.

## Демонстрация на GitHub Pages

Ветка `gh-pages` публикует доступную только для чтения копию архива. Она включает все восстановленные страницы, локальные медиа и поиск по сохранённым материалам. GitHub Pages не запускает Node.js, SQLite и административную часть — полноценная CMS разворачивается через Docker.

Для пользовательского репозитория `Kibosh13.github.io` демонстрация открывается по адресу `https://kibosh13.github.io/`. Статическую копию формирует команда `python3 scripts/build_github_pages.py --output <каталог>`, после чего содержимое каталога публикуется в ветку `gh-pages`.

## Резервные копии

Для обычного запуска резервируйте всю папку `storage`: в ней лежат `cms.sqlite` и `uploads`. Перед простым копированием остановите приложение, чтобы вместе с базой не остались несохранённые WAL-файлы.

Для Docker остановите только приложение и упакуйте том:

```bash
docker compose stop site
mkdir -p backups
docker run --rm -v vestniki-peremen_cms-data:/data -v "$PWD/backups:/backup" alpine tar -czf /backup/cms-data.tar.gz -C /data .
docker compose start site
```

Имя тома зависит от имени папки/проекта Docker Compose. Его можно проверить командой `docker volume ls`.

В резервную копию должны входить и база, и папка загрузок. Периодически проверяйте восстановление копии на отдельном сервере.

## Что не отправлять в Git

Файлы `.env*`, папка `storage`, SQLite-база, загруженные пользователями материалы и резервные копии содержат секреты или изменяемые данные и уже исключены из репозитория. В Git отправляется код, миграции, восстановленный публичный архив и исходный набор новостей для первого импорта.

Публичный архив занимает сотни мегабайт и хранится непосредственно в репозитории, чтобы GitHub Pages мог публиковать его без внешнего хранилища. Не добавляйте в историю повторные копии архива: при будущей миграции крупных медиа предпочтительнее объектное хранилище.

## Важные переменные окружения

- `CMS_ADMIN_EMAIL`, `CMS_ADMIN_NAME`, `CMS_ADMIN_PASSWORD` — первый администратор;
- `CMS_DATA_DIR` — каталог SQLite и загрузок;
- `CMS_IMPORT_NEWS` — однократный импорт сохранённых новостей;
- `CMS_NEWS_SEED_PATH` — необязательный путь к другому файлу импорта;
- `SITE_URL` — канонический HTTPS-адрес нового сайта.
